# ADR 0024 · The website: static pages generated in Rust from the signed catalog

- **Status:** accepted
- **Date:** 2026-11-10

## Decision

- The website lives on **GitHub Pages**, at `https://alvaritoo89.github.io/Locall/` (free with the public repository;
  no custom domain for now, one can be added later without redoing anything).
- It is **generated by our own Rust program** (`crates/locall-web`) from `catalogo/catalogo.json`:
  - the website and the app always say the same thing (same source);
  - **it refuses to generate anything if the catalog does not carry a valid official signature**: an unsigned catalog
    is never published;
  - no new dependencies (only `locall-catalogo`): the HTML is written by hand and **all catalog text is escaped**, even
    though it is signed (there is a test with malicious text);
  - it only empties its output folder if the folder is empty or was created by the generator itself (it carries a
    marker): a wrong path never deletes anything.
- Astro, Hugo and Jekyll were rejected: they would add a toolchain and dozens or hundreds of dependencies for a few
  pages.
- Pages: home, download («Próximamente» / coming soon, until the signed installer of Phase 8), models (with filters by
  use and size), one per model (with its `locall pull` command to copy, its data and its sha256), privacy and 404.
  Everything says «compatible», never «probado» / tested (ADR 0022). Neither the author's computer nor speeds.
- **Nothing external:** no cookies, no analytics, no Google Fonts (Inter and JetBrains Mono are served by the site,
  with their OFL license). Only links to GitHub and Hugging Face. The privacy page says GitHub logs visitors' IP
  addresses (according to its documentation).
- **Search on the models page** (with JavaScript): typing filters the catalog **without sending anything**; the
  «Buscar en Hugging Face» button searches all GGUF models on Hugging Face **from the visitor's browser** (Hugging Face
  allows it: its API authorizes the `alvaritoo89.github.io` origin, checked on 2026-11-10). Only then is the text sent,
  and the page says so next to the button and on the privacy page. The request is sent without cookies or `Referer`,
  and results are rendered with `textContent` (never as HTML). Each result shows its `locall pull owner/name` and a
  note that it is not in the catalog.
- **It works without JavaScript.** The script (`web/estaticos/web.js`, no dependencies) only adds the Copy buttons, the
  filters and the search.
- The site also carries a copy of the catalog and its signature (`catalogo/`). The app still downloads it from
  raw.githubusercontent.com (ADR 0023).

## Publishing (`.github/workflows/web.yml`)

- On pushes that change the catalog, the website or the generator: tests → generate → publish.
- Every GitHub action is **pinned to a commit** (checkout v7.0.1, upload-pages-artifact v5.0.0, deploy-pages v5.0.1),
  the build job can only read the repository, and the publishing job is the only one with Pages permission.
- Rust 1.99.1, the same version as in development.
- Requirement (once, done by the author): Settings → Pages → Source: **GitHub Actions**.

## Consequences

- Cost €0. GitHub Pages limits: 1 GB of site and 100 GB of traffic per month (soft limits), no commercial use.
- Changing the website's text means touching `crates/locall-web/src/lib.rs`; the models, the catalog (and signing it
  again).
