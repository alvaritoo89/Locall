# ADR 0032 · Phase 8b: the Windows installer

- **Status:** accepted
- **Date:** 2026-11-12

## Decision

Locall is installed with an **NSIS `setup.exe` generated by Tauri** (the author's choice), **per user**: no
administrator rights, no UAC prompt. `scripts/construir_instalador.ps1` builds it in one go: `locall.exe` in release
mode, the verified engine and the third-party notices (ADR 0031), the UI, and finally `tauri build` with an
installer-only configuration (`crates/locall-app/instalador/tauri.instalador.conf.json`). That configuration lives in
a separate file so that normal builds and the CI do not need the engine prepared (Tauri copies resources at build time
and fails if they are missing).

**Install folder: `%LOCALAPPDATA%\Programs\Locall`.** Tauri's default for per-user installs is
`%LOCALAPPDATA%\<product name>`, which for us is `%LOCALAPPDATA%\Locall`: **the same folder as the user's data**
(models, conversations, settings, logs). Tauri's uninstaller only removes that folder if it is empty, so data would not
be lost, but mixing the program with the data is wrong (updates, backups, cleaning). Tauri has no option for this, so
`instalador/installer.nsi` is a copy of Tauri's official template **for exactly tauri-cli 2.12.4** with one line changed
(marked "Locall:"). It must be copied again when tauri-cli is updated. `%LOCALAPPDATA%\Programs` is where Windows
expects per-user programs (VS Code and Ollama install there too).

**Contents** (as defined in ADR 0031): `locall-app.exe`, `locall.exe`, `motor\` (24 files), `LICENSE.txt`,
`THIRD-PARTY-NOTICES.txt` and the uninstaller. About 14 MB compressed.

**Installer steps** (`instalador/ganchos.nsh`, hooks that Tauri's template calls):

- Before installing (also when updating) and before uninstalling: `locall stop`, so a running core does not keep its
  files locked. The app window is already handled by Tauri's template.
- After installing: `locall.exe --instalador-anadir-al-path` adds the install folder to the **user's** `PATH`, so
  `locall` works in any new terminal. Before uninstalling: `--instalador-quitar-del-path` removes it.

The `PATH` is changed by `locall.exe` itself, in Rust (`locall_system::anadir_al_path_del_usuario` /
`quitar_del_path_del_usuario`), not in NSIS: NSIS works with strings of limited length and could **truncate** a long
`PATH`, damaging the user's whole environment. The Rust code reads `HKCU\Environment\Path` with no length limit, keeps
its type (`REG_EXPAND_SZ`, so `%VARIABLES%` keep working), adds or removes only our folder (ignoring case, quotes and a
final backslash; every other entry stays exactly as it was) and tells Windows the environment changed. Those two
options are not shown in the help: they are for the installer.

**User data is never touched by the installer or the uninstaller.** Uninstalling Locall keeps
`%LOCALAPPDATA%\Locall`. Tauri's optional "delete app data" checkbox only removes the WebView's own folder
(`%LOCALAPPDATA%\io.github.alvaritoo89.locall`).

Installer languages: Spanish and English, chosen from the system language without asking. The installer offers a
desktop shortcut (Tauri's default) and creates one in the Start menu.

The first build downloads Tauri's NSIS tools (NSIS 3.13 and its helper plugin), which Tauri checks by hash. NSIS's
installer stub is under the zlib license, which does not require a notice in binaries. No new dependency in the
project.

## Tests

- PATH: unit tests of adding and removing (duplicates, case, quotes, final backslash, `%VARIABLES%`, empty entries)
  and a round trip in the registry with a key of the test's own (`HKCU\Software\Locall-pruebas`, deleted afterwards),
  never the user's real `Environment`.
- Real install and uninstall on the author's computer (with their permission), silently (`/S`): files in
  `%LOCALAPPDATA%\Programs\Locall`, engine with its 24 files, the entry in Installed apps, Start menu and desktop
  shortcuts, the folder added to the `PATH` with its type kept, `where locall` finds it from a fresh `PATH`, the
  installed `locall status` and `llama-server --version` work. After uninstalling: folder, entry and shortcuts are
  gone, the `PATH` is **identical character for character** to before, and the user's 13 data files are unchanged
  (name, size and date).
